- Severity: blocker
  File: app/controllers/issue_templates_controller.rb:239-259
  Problem: Authorization bypass in loadable? for project templates shared with subprojects. The check permits loading a template if the user has show_issue_templates in any descendant of the template’s project, regardless of the actual project the request is for (params[:project_id] is ignored for project templates). This lets a user who has permission in descendant A load a shared template while on descendant B where they lack the permission.
  Concrete failure scenario: Project P has two subprojects A and B. A user has show_issue_templates in A only. A template T in P is shared with subprojects (enabled_sharing?). From B’s new issue form (project_id=B), the user can POST /issue_templates/load with template_id=T and receives the template JSON (200) because loadable? returns true due to permission in some descendant (A), leaking template data into B where the user should get 403.
  Fix: Tie the authorization to the requesting project. For project templates:
    - Determine the current project from params[:project_id] (id or identifier).
    - Return true if current_project == issue_template.project and allowed_to? there.
    - Or, if issue_template.enabled_sharing? AND current_project is a descendant of issue_template.project AND the user is allowed_to? in current_project.
    - Otherwise return false.
    Example patch:
      def loadable?(issue_template)
        return global_template_loadable?(issue_template) if issue_template.is_a?(GlobalIssueTemplate)
        template_project = issue_template.project
        current_project = Project.find_by(id: params[:project_id]) || Project.find_by(identifier: params[:project_id])
        return false unless current_project
        return true if User.current.allowed_to?(:show_issue_templates, template_project) && current_project == template_project
        issue_template.enabled_sharing? &&
          current_project.is_descendant_of?(template_project) &&
          User.current.allowed_to?(:show_issue_templates, current_project)
      end

  Resolution: fixed in the commit after cb732a1 ("Tie template loading to the project of the issue
  form"), with test_load_returns_a_template_shared_with_a_subproject extended to a subproject without the
  permission and a subproject that does not inherit (both 200 before, 403 now). load now decides on the
  request's project the way the pulldown offers templates: the project's own, a shared ancestor
  template only when the project inherits templates, global templates assigned to it (or to all).

  find_by(identifier:) would read identifier "1abc" as id 1); that lookup is replaced by Project.find
