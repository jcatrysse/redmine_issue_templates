Problem: The tracker display logic now shows “Orphaned template from tracker” for any persisted template regardless of whether a tracker is present. Previously it showed the actual tracker name when present.

<% elsif issue_template.persisted? %>

Resolution: not changed, not a bug: the line sits inside `<% if issue_template.tracker.blank? %>` (the branch for a template without tracker); a template with a tracker takes the `else` branch and never shows it. Before this change that branch printed the message on a new form too (the tracker.present? test there was always false); now only a saved template without tracker shows it. Covered by test_new_form_does_not_call_the_template_orphaned and the issue-template test that sets tracker 999 (8d0c73f).

Major, lib/issue_templates/journals_hook.rb:59
Problem: Uses context[:journal]&.issue to fetch the issue from a journal. In Redmine 7 Journal does not reliably expose an issue method (it has the polymorphic journalized association). Safe navigation &. only avoids calling the method when the receiver is nil; it will still raise NoMethodError if Journal doesn’t respond to :issue.
Failure scenario: A hook is invoked on a journal-related view with context containing {project: nil, journal: <Journal of an Issue>}. tracker_project_ids calls context[:journal]&.issue, raising NoMethodError: undefined method 'issue' for #<Journal …>, resulting in a 500 error when viewing an issue’s history or notes.
Fix: Derive the issue from the polymorphic association and guard the type. For example:
  def tracker_project_ids(context, tracker_id)
    project = context[:project]
    journal = context[:journal]
    issue   = context[:issue] || (journal&.journalized.is_a?(Issue) ? journal.journalized : nil)
    project_id = project.present? ? project.id : issue&.project_id
    [tracker_id, project_id]
  end
Alternatively, use journal.respond_to?(:issue) ? journal.issue : journal&.journalized if journalized is an Issue.

Resolution: not changed, not a bug: Journal in Redmine 7.0 has `belongs_to :issue, :foreign_key => :journalized_id` (app/models/journal.rb:27 of 7.0-stable-GEOxyz), so `journal.issue` is the issue; the hooks that pass a journal are on issue pages only. Covered by test/unit/journals_hook_test.rb (418636f).
